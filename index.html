0.1 HTML basics

Element

A tag pair plus its content, like <p>Hello</p>. Elements nest inside each other to form a tree.

Attribute

Extra information on a tag, such as href on a link or alt on an image.

DOM

The browser turns your HTML into a tree called the Document Object Model. CSS and JavaScript work on that tree.

class and id

A class can repeat and is how CSS targets groups. An id must be unique on the page.

Common tags

<h1> heading, <p> paragraph, <a> link, <img> picture, <ul> list, <button> action, <nav> navigation, <main> main content.

Forms and labels

A <form> groups inputs. Every <input> needs a <label for="id"> so screen readers and click targets work. Use the right type: email, password, number, date.

Page layout tags

<header>, <nav>, <main>, <aside> and <footer> describe regions. Use <div> only when nothing semantic fits.

Tables

Use <table> for tabular data only, with <th> header cells. Financial lists such as transactions are tables.

Accessibility basics

Keep headings in order (h1, then h2). Give images alt text. Make sure everything works with the keyboard. Keep text contrast high.

0.2 CSS basics

Main axis and cross axis

justify-content spaces items along the main axis. align-items aligns them across it. flex-direction decides which way the main axis points.

Box model

Every element is content, then padding, then border, then margin. Padding is space inside the card. Margin is space outside it. gap is space between children.

Selectors and specificity

A selector picks elements: p by tag, .card by class, #hero by id. When rules clash, the more specific selector wins: id beats class, class beats tag.

Units

px is fixed. rem scales with the root font size. % follows the parent. fr is a share of free grid space.

Typography

font-family sets the typeface, font-size the size, font-weight the boldness (400 regular, 500 medium, 600 semibold, 700 bold) and line-height the spacing between lines.

Display and position

block fills the row, inline flows in text, flex and grid lay out children. position: sticky keeps a header visible while scrolling.

Responsive design

Use a media query such as @media (max-width: 600px) to change layout on small screens. Prefer fluid units and auto-fit grids first.

Hover and transitions

:hover styles a state. transition: all .3s animates the change smoothly.

Container queries

A media query reacts to the browser window. A container query reacts to the parent component, so the same card fits a narrow sidebar or a wide page. The parent needs container-type: inline-size and a name. The child then uses @container name (max-width: 960px).

0.3 Theme variables

Design token

A named value such as --md-sys-color-primary. Components read the name, never a hard-coded colour.

Defining and reading

Define on :root or a theme class like .dark-theme. Read with var(--name, fallback). The fallback is used if the variable is missing.

Cascade and scope

A variable is inherited by every child. Redefine it on a card and only that card changes. Redefine it on .dark-theme and the whole app switches.

Nesting with &

In nested rules, &:hover compiles to .btn:hover and &.no-border means the same element also has .no-border.

Naming by role

Name tokens for what they do, not what they look like: --md-sys-color-primary, not --lime.

Scales

Spacing, radius and type sizes come in steps (small, medium, large) so designs stay consistent.

Per-client themes

Each client overrides only the tokens it needs, for example in a .tenant-acme class. Everything else is inherited.

Utility classes

Theme files ship classes like .card and .text-body-medium that read tokens, so teams style by class instead of writing new CSS.

0.5 Theme JSON

What is a theme JSON?

An object where each key is a selector and each value holds CSS properties. Keys can be camelCase (backgroundColor) or kebab-case. It compiles to normal CSS.

Structure of the default template

":root" holds ".light-theme" and ".dark-theme", which define the tokens. Next come an @font-face block, global rules such as "*" and "body", then component classes.

Nesting and at-rules

"&:hover" means the parent selector in hover. At-rules such as @media and @container can be nested inside a selector and apply to it.

User and client overrides

Keep the default theme untouched. Add an override that lists only the changed tokens. It is merged on top, so later values win.

Valid JSON rules

Use double quotes, no comments and no trailing commas. Numbers such as 0 are allowed, but sizes usually need a unit like "8px".

0.4 Financial dashboards

KPI card

One headline number with a label and a change indicator, like Active Balance or Total Earnings. It answers one question at a glance.

Chart types

Line for trends over time. Bar to compare categories. Donut for share of a total. Use the simplest chart that answers the question.

Data flow

API returns JSON, the app stores it in state, and components render it. Charts and KPIs are functions of the data, so changing the data redraws them.

Number formatting

Format with Intl.NumberFormat so currency, separators and decimals follow the locale. Use tabular numbers so digits line up in columns.

Semantic colour

Green for gains, red for losses, always with a sign (+ or −) too. Never rely on colour alone.

UI states

Every widget needs loading (skeleton), empty and error states, not just the happy path.

Reading a Figma spec

Select a layer and open Inspect. Copy font-family, font-size, font-weight, colour, padding, margin, gap and radius exactly. Convert design values to tokens where they exist.

Compact and percent formats

Intl.NumberFormat can show 1.2M with notation: "compact" and 12.4% with style: "percent".

Time ranges

Charts usually offer 1D, 1W, 1M, 1Y. Changing the range refetches or filters the data, and the chart redraws.

Performance

Long transaction lists use pagination or virtual scrolling. Avoid redrawing every chart on each keystroke.

Safety

Treat API data as untrusted. Set text with textContent or escape it before inserting HTML.
